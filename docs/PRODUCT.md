# AI Stock 产品文档

> 版本：v0.5.14 ｜ 许可证：Apache-2.0 ｜ 上游框架：[TradingAgents](https://github.com/TauricResearch/TradingAgents)

## 1. 产品概述

**AI Stock（ai-stock）** 是一套面向 **A 股（中国大陆股票市场）** 的**多智能体（Multi-Agent）投研辅助系统**。它将一篇完整的个股研究报告拆解为一条"分析师 → 质量门控 → 多空辩论 → 研究经理 → 交易员 → 风险辩论 → 组合决策"的 LLM 流水线，由多个角色化的智能体分工完成，最终产出一份带**数据质量评级**与**五档投资评级**的结构化研究结论。

与传统"单次提问、单份回答"的 ChatGPT 式分析不同，AI Stock 的核心价值在于：

| 差异点 | 说明 |
|---|---|
| **多角色制衡** | 多头与空头强制辩论、激进/稳健/中性三方风险辩论，避免单一模型的确认偏误 |
| **数据落地** | 7 家国内公开数据源（通达信/腾讯/东财/新浪/同花顺/财联社/百度）真实取数，而非模型凭记忆编造 |
| **数据质量门控** | 每份分析师报告先过代码硬检查，再过 LLM 复审，评级（A–F）随报告流向下游，低质量数据会被自动降权 |
| **防未来函数** | 内建 point-in-time 防护：复盘历史日期时自动截断实时资金流、快照数据带显著标注，避免"用今天的答案回答昨天的问题" |
| **记忆与绩效** | 每次评级先登记为 pending，若干交易日后拉取真实行情结算收益与超额，形成方向正确率统计并注入后续分析 |
| **可自进化** | 支持以 Markdown 编写自定义策略，由系统按市场状态（牛/熊/震荡）分配权重注入各角色提示词 |

> **定位声明**：本项目为**研究与教学用途**的开源框架，输出为研究性评级，不构成投资建议，不接入实盘交易。

## 2. 目标用户

| 用户群 | 场景 |
|---|---|
| 个人投资者（具备编程基础） | 本地部署，对自选股做多角度深度研究，替代"手动翻 F10 + 问 ChatGPT" |
| 量化/金融工程学习者 | 研究多 Agent 协作范式、LangGraph 编排、辩论式决策、point-in-time 数据工程 |
| LLM 应用开发者 | 将本框架作为多 Agent + 工具调用 + 断点续跑 + 记忆系统的参考实现，二次开发 |
| 小型投研团队 | 部署前后端分离版，多用户共享一套分析引擎与历史报告库 |

## 3. 产品形态

AI Stock 同一套分析引擎提供 **三种使用形态**：

### 3.1 CLI 命令行（`ai-stock`）

安装后即可使用的终端交互界面（基于 typer + questionary + rich）：

- 交互式选择股票（支持 6 位代码或中文名，如 `600519` / `贵州茅台`）
- 选择分析日期、分析师组合、回看窗口
- 终端实时展示各阶段进度、工具调用次数、LLM token 消耗
- 分析完成后直接输出最终决策与报告路径

### 3.2 Web 平台（前后端分离版）

- **后端**：FastAPI（端口 8000），提供用户注册/登录（JWT）、分析任务管理、实时行情/K 线、历史报告、PDF 导出、自选股管理、新闻影响榜与个股推荐等 REST API（Swagger 文档见 `/docs`）
- **前端**：Vue 3 + Element Plus（端口 5173），页面包括工作台、分析页（进度追踪 + 报告阅读器 + K 线图）、历史报告、新闻影响榜、个股推荐、登录/注册
- 多用户隔离：每个分析任务归属登录用户，LLM 配置按任务快照入库

### 3.3 自动化流水线（pipeline 模块）

由 APScheduler 驱动的**新闻影响分析流水线**，无需人工发起：

```
新闻采集 → 预过滤 → LLM 影响打分 → 供需分析 → 多空辩论
→ Top20 影响榜 → 候选池 → 三维打分 → 个股辩论 → 推荐列表
```

产出两个面向用户的结果：**新闻影响排行**（哪些新闻在驱动市场）与**个股推荐列表**（按多维评分排序）。

## 4. 核心功能

### 4.1 六分析师矩阵

| 分析师 | 角色 | 主要数据能力 |
|---|---|---|
| **技术分析师**（market） | 价格与指标结构 | 日线 OHLCV（通达信，新浪兜底）、MACD/KDJ/RSI 等技术指标 |
| **情绪分析师**（social） | 舆情与资金情绪 | 社交媒体情绪、龙虎榜席位、个股资金流 |
| **新闻分析师**（news） | 事件与信息面 | 东财/新浪/财联社个股新闻、公告快讯 |
| **基本面分析师**（fundamentals） | 财务与估值 | 三大报表（新浪）、同花顺 EPS 一致预期、行业横向对比、限售解禁日历 |
| **政策分析师**（policy） | 宏观与产业政策 | 政策新闻流、行业政策影响分析 |
| **游资追踪师**（hot_money） | 短线资金行为 | 连板天梯、涨停原因归类、题材归因、市场情绪温度计、北向资金 |

各分析师是"LLM + 工具集"的 ReAct 智能体：模型自主决定调用哪些数据工具、调用几次，直到认为证据充分才写报告。分析师组合可由用户按需勾选（例如只跑基本面 + 政策）。

### 4.2 数据质量门控（Quality Gate）

分析师产出后、辩论开始前，系统对每份报告执行两层校验：

1. **硬检查（代码层）**：报告是否为空、长度是否达标、是否主要由"无法获取数据"类失败信息构成、是否含汇总表格、数据缺失处数量 → 评级 A/B/C/D/F
2. **LLM 复审（模型层）**：对通过硬检查的报告做一次整体审核，输出数据时效性核对与"建议辩论阶段谨慎使用 XX 报告"的提示

质量摘要会**注入下游所有辩论与决策节点的提示词**——多头/空头辩手被明确要求"对 C/D/F 级报告降低依赖并说明数据局限"，这是防止模型被低质量数据带偏的关键机制。

### 4.3 多空辩论

- **多头研究员**：以上市公司增长逻辑、A 股特有催化（政策红利、北向流入、游资接力、估值消化路径）构建买入论证
- **空头研究员**：以估值风险、财务隐患、筹码结构、监管风险构建卖出论证
- 双方交替发言、直接引用并反驳对方论点，默认 1 轮（可配置到多轮），全程基于六份报告中的真实数据

### 4.4 研究经理（Research Manager）

使用"深度思考"档模型，通读辩论全程记录，产出结构化的 **ResearchPlan**（研究结论），对多空论点做证据强度对比与裁决。

### 4.5 交易员提案（Trader）

将研究结论翻译为贴近 A 股交易规则的 **TraderProposal**：倾向方向（买入/增持/持有/减持/卖出/观望）、逻辑链与风险清单。提示词内建 A 股约束：T+1、涨跌停幅度、100 股整数手、交易时段、重大事项停牌等。按项目研究定位，提案**不包含可执行价位与仓位数字**。

### 4.6 风险三方辩论

交易员提案交由三方风险官质询：

| 风险官 | 立场 |
|---|---|
| 激进派 | 论证为何可以承受风险、机会成本 |
| 稳健派 | 论证最坏情景、需要什么条件才参与 |
| 中性派 | 权衡双方，给出条件化结论 |

### 4.7 组合决策（Portfolio Manager）

流水线终点。以"深度思考"档模型综合全部材料，输出最终 **PortfolioDecision**：

- **五档评级**：`Buy / Overweight / Hold / Underweight / Sell`（研究性评级）
- 决策逻辑、关键风险、反向信号（什么情况下该推翻本次结论）
- A 股合规与市场结构约束下的操作注意事项

### 4.8 记忆与绩效统计

- 每次分析结束后，评级以 `[日期 | 代码 | 评级 | 收益% | 超额% | 持有天数]` 标签写入记忆日志（`~/.tradingagents/memory/trading_memory.md`，原子写入）
- N 个交易日后自动**结算**：拉取真实行情回填实际收益与相对基准超额收益
- 结算条目经反思提炼后形成 REFLECTION 段落，**注入后续同标的分析**的各辩论节点提示词（"上次我们说……实际走势……"）
- 内建绩效统计口径：方向正确率（Hold 不计入）、评级单调性检验（Buy 是否平均跑赢 Sell）、最小有效样本量 20 条——样本不足时明确提示统计无意义

### 4.9 自进化策略层（可选）

- 用户以 Markdown 文件编写自定义策略（`custom_strategies/` 下按牛/熊/震荡/题材/风险等 12 类目录组织）
- 系统根据市场状态识别结果，为每个角色动态分配策略权重并注入提示词
- 历史辩论经验存入向量库（Chroma），相似场景自动检索 Top-K 经验回放
- 该层为可选依赖：未安装 chromadb 时自动降级为关闭，不影响主流程

### 4.10 断点续跑（Checkpoint/Resume）

开启 `checkpoint_enabled` 后，LangGraph 在每个节点执行后保存状态快照（per-ticker SQLite）。进程崩溃或主动暂停后，可从**最后一个成功节点**恢复，不重复消耗已完成阶段的 LLM 费用。Web 与 CLI 均提供"未完成任务"列表与续跑入口。

### 4.11 报告管理

- 全量状态日志按 `~/.tradingagents/logs/<ticker>/<日期>/` 归档（JSON）
- Web 端支持历史列表、报告在线阅读（Markdown 渲染）、PDF 导出（内建中文字体探测，Docker 镜像已预装 CJK 字体）
- 报告含全部中间产物：六份分析师报告、质量门控摘要、辩论全程、最终决策

## 5. 用户旅程（Web 平台示例）

1. **注册/登录** → 进入工作台
2. **发起分析**：搜索股票（代码/中文名）→ 选择分析师组合、分析日期、回看窗口 → 可选 LLM 配置 → 点击开始
3. **跟踪进度**：进度面板按 11 个阶段实时展示（分析师生成中 → 质量门控 → 多空辩论 → … → 组合决策），支持**暂停/恢复/终止**
4. **阅读报告**：报告阅读器分节展示决策摘要、各分析师报告、辩论记录；K 线图联动
5. **导出归档**：下载 Markdown/PDF，或从历史页随时回看
6. **复盘迭代**：数日后查看记忆结算结果；在新闻影响榜/推荐页发现新标的

## 6. 输出物规格

| 输出物 | 格式 | 内容 |
|---|---|---|
| 最终决策 | 结构化 JSON + Markdown 渲染 | 五档评级、决策逻辑、关键风险、反向信号 |
| 分析师报告 | Markdown | 各分析师完整报告（含数据表格） |
| 质量摘要 | Markdown | 各报告 A–F 评级与 LLM 复审意见 |
| 辩论记录 | Markdown | 多空辩论、风险三方辩论全文 |
| 全量日志 | JSON | 每次分析的完整状态快照（供回放/审计） |
| 导出文件 | .md / .pdf | 面向分享的成稿 |

## 7. 功能边界

**做**：
- A 股个股（沪深主板/创业板/科创板/北交所，6 位数字代码）的多角度研究
- 任意历史交易日的复盘分析（point-in-time 防未来函数）
- 多用户、多任务并发的分析平台化管理

**不做**：
- 港股/美股（检测到非 A 股代码会明确报错并指向姊妹项目）
- 实盘交易接口、自动下单
- 实时盘中 tick 级监控（数据源为公开日线/快照接口）
- 投资建议承诺：所有输出均为研究性质

## 8. 已知限制

1. **数据源为免费公开接口**：无 SLA，高峰期可能限流/封禁（系统已内建节流与多级 fallback，但仍可能失败）
2. **LLM 成本**：一次完整分析涉及 10+ 个节点、多次工具调用循环，token 消耗显著；建议分析师按需勾选
3. **免费档 LLM 结构化输出质量**：五档评级解析对模型指令跟随能力有要求，推荐使用 DeepSeek 及以上能力档位
4. **记忆结算依赖外部行情**：结算收益需可访问 yfinance 或等效行情源（见技术文档已知问题章节）
5. **Windows 文件占用**：Windows 杀毒软件扫描可能导致日志/索引短暂占用（已内建重试与降级写入）

## 9. 常见问题（FAQ）

**Q：分析一个股票要多久、花多少钱？**
取决于所选分析师数量与辩论轮数。默认配置（6 分析师 + 1 轮辩论）下，主要耗时在分析师工具调用循环；使用 DeepSeek 等低价模型单次完整分析通常在数毛至数元人民币量级。

**Q：结果可以直接照着操作吗？**
不可以。输出是研究性评级，不含可执行价位与仓位；请结合自身判断使用，详见仓库 `NOTICE`。

**Q：可以只分析某几个维度吗？**
可以。CLI/Web 均支持勾选分析师子集（注意：CLI 当前版本的分析师菜单尚未包含政策与游资两项，见技术文档已知问题 B6）。

**Q：分析中途断网/崩溃怎么办？**
开启 `checkpoint_enabled` 后可从断点恢复；未开启则需重跑。Web 端"未完成任务"列表会给出可续跑任务。

**Q：换模型厂商麻烦吗？**
不麻烦。所有形态（CLI/Web/Pipeline）统一读取项目根 `.env` 中的 `LLM_PROVIDER` + `LLM_MODEL` + 对应 API Key，改完重启即生效。支持按角色配置不同厂商模型（如多头用 DeepSeek、空头用 Qwen，以获得真实的观点对抗）。
