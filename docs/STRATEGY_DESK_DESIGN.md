# 策略台（StrategyDesk）产品设计方案

> 版本：v1.0 ｜ 日期：2026-10-25 ｜ 定位：把「股市分析专家团」的方法论固化为 ai_stock 的常驻分析层
> 上游依据：《专家团 vs ai_stock agents 对比分析》（`expert_team_vs_ai_stock_agents.md`）
> 设计约束：不引入新数据供应商（宏观除外）、不改动交易链路硬门槛、全部新表靠 `create_all` 建

---

## 1. 问题定义（为什么做）

对比结论的可用部分是这一句：**ai_stock 是「更强的数据管道 + 更弱的分析框架」**。

具体缺口只有 5 项，且其中 3 项与数据无关：

| # | 缺口 | 性质 | 后果 |
|---|---|---|---|
| G1 | 无板块内结构拆解 | 框架 | 只知道"板块涨了"，不知道"涨的是哪一拨"，选股会买错分支 |
| G2 | 无高标溯源 | 框架 | 把并购重组妖股当成板块启动，是**最贵的归因错误**（会直接买到跟风票） |
| G3 | 无交叉验证矩阵 | 框架 | 单一视角下结论，无法识别"边拉边撤""有新闻无资金" |
| G4 | 无记分闭环 | 框架 | 错了不知道为什么错，系统性偏差永远发现不了 |
| G5 | 无宏观 regime 闸门 | 数据 + 框架 | 无法给出"当前该不该给成长板块高评级"的约束 |

**产品机会**：专家团是"人读的报告"，ai_stock 是"机器执行的系统"。真正的差异化不是复刻一份报告，而是**把专家的判断变成可回填的数据，再用回填结果反过来调机器的权重**——这件事专家团做不到（它没有 DB 和交易链路），而这恰好是 ai_stock 最大的存量优势。

---

## 2. 产品定位与场景

**一句话定位**：让 ai_stock 每天收盘后用**可验证的证据链**回答三个问题——今天涨的是哪一拨、这拨能不能持续、我们上一次判断错在哪——并把答案变成次日选股的权重。

| 场景 | 时间 | 用户动作 | 系统产出 |
|---|---|---|---|
| **盘后复盘**（主场景） | 15:05–15:30 | 打开「策略台」，3 分钟看完 | 三段式报告 + 结构拆解表 + 高标梯队卡 |
| **盘前决策** | 次日 09:00 | 看昨日评级与今日关注池 | 关注板块表 + 龙头（含角色）+ 事件日历 |
| **周度校准** | 周末 | 看记分看板 | 分组胜率、校准曲线、偏差诊断 |
| **系统自用**（无界面） | 次日选股 | 无需动作 | 评级 → 行业优先级权重 / 二次验证上下文 |

## 3. 产品原则（五条硬约束，写进代码而非文档）

1. **证据引用制**：报告里每一条结论必须挂 `evidence_id[]`。裁决器校验不通过的断言，自动降级为「观点」并标灰，不计入记分。**这是压制 LLM 编数据的唯一有效手段**——专家团靠人自觉，系统靠外键。
2. **结构化落库优先**：先出 JSON（可回填、可统计），再渲染成文字。禁止只产出散文。
3. **双向服务**：报告既给人看，也给 `selection` / `second_verification` 消费。**不做只读的死报告。**
4. **降级不猜**：数据缺失标「数据缺失」，样本不足标「观察」，不得用估计值填充，不得为了凑数把 1 只有证据的票包装成板块。
5. **渐进反哺**：分析结论进入交易链路只走**权重系数**（±20% 内），**绝不作为硬门槛**。项目已因硬门槛吃过「全天零交易」的亏（见 `handle_buy_scan` 历史事故）。

## 4. 信息架构

新增一个一级入口「策略台」（`/strategy`），单页三 Tab + 一份报告：

```
策略台
├─ Tab1 市场状态（当日定论）
│   ├─ 数据时点戳（收盘 15:00 / ⚠️盘中 HH:MM 未定局）
│   ├─ 六条总览：小结｜资金｜情绪｜风格｜宏观 regime｜主线阶段
│   ├─ 高标梯队与溯源表（连板数/真实驱动/归属类型/资金验证）
│   └─ 风险提示 ×3
├─ Tab2 关注板块（核心工作区）
│   ├─ 板块总表（8 列：板块｜驱动｜强热程度｜预测｜阶段｜依据｜事件日历｜龙头+角色）
│   ├─ 点开任一板块 → 结构拆解抽屉（basket 成分、合成涨跌幅、证据等级、驱动一致性）
│   └─ 交叉验证矩阵（板块面/资金面/新闻面 三列 + 一致性判定 + 伪共振标记）
└─ Tab3 记分（复盘区）
    ├─ 累计胜率 / 赔率 / 校准曲线
    ├─ 按 driver 分组胜率（识别"我们是否总把游资脉冲当主线"）
    └─ 待验证断言清单（可一键回填）
```

**报告形态固定为三段式**（与专家团输出规范一致，不允许退回多节结构）：① 大盘总览（逐条）② 关注板块（表格）③ 交易建议（可操作）。

## 5. 功能模块设计（M1–M6）

### M1 板块结构拆解器（对应 G1）

| 项 | 内容 |
|---|---|
| 目标 | 把"某板块涨了"拆成"哪个子篮子涨了、涨的驱动是否同源" |
| 输入 | `get_all_board_fund_flow()` 涨幅前 5 板块 → `get_industry_stocks()` 成分股 → `get_limit_up_stocks()` reason_tags → `get_concept_blocks()` 细分归属 |
| 处理 | ① 用 reason_tags + 概念归属对成分股做**软聚类**，产出候选 basket（≥3 只才成为候选）② 计算合成涨跌幅（等权）与对板块的贡献度 ③ **驱动一致性校验**：逐只判 `driver`，`driver ∈ {并购重组, 借壳, 易主}` 的强制 `exclude=1` ④ **证据分级 A/B/C/D**，D 级不计入有效样本 |
| 输出 | `strategy_structure_basket`：basket 名、成分、合成涨跌幅、有效样本数、证据分布、驱动一致性、**评级上限** |
| 硬规则（固化为代码，`basket_validator`） | 有效样本 ≥8 → 最高「强」；5–7 → 最高「中」；<5 → 只能「观察」；**有证据样本 =1 → 只能写「个股事件」，禁止出现板块评级** |
| 复用 | `DataService` 现有 5 个方法，零新增数据源 |
| 验收 | 回放已知四个反例（家电无 L3 / 锂矿 2 只 / 航运 3 只 / CPO 5 只里仅 1 只有证据），系统必须**自动**给出"观察"或"个股事件"，不得给板块评级 |

> **为什么这是 P0**：这是专家团连续复发三次的系统性错误，也是"买了跟风票"的直接原因。把它变成代码规则，比三份报告更有价值。

### M2 高标溯源器（对应 G2）

| 项 | 内容 |
|---|---|
| 目标 | 回答"最高标在涨什么、能不能外推为板块" |
| 输入 | `get_limit_up_stocks(days=5)`（连续多日 → 自行算连板数）、`get_dragon_tiger_board()`、`get_fund_flow()`、`get_hot_news()` |
| 处理 | ① 连板数聚合 → 梯队（最高标/第二梯队/断层判定）② 驱动分类：`子概念龙头 / 独立事件(并购重组·借壳·易主) / 纯情绪 / 无公开催化` ③ 若 `独立事件` 或 `无公告` → `extrapolable=0`，并从所有 basket 中剔除后重算 ④ 资金验证：`机构承接 / 游资接力 / 边拉边撤`（龙虎榜席位性质 + 当日资金流符号） |
| 输出 | `strategy_leader_trace`：symbol、连板数、板型、官方板块、**真实驱动**、**归属类型**、资金验证、`extrapolable`、`exclude_flag` |
| 产品细节 | 前端高标卡片**必须显式显示**"该股为并购重组独立事件，不可外推为板块"，避免用户误读 |
| 验收 | 5 日内出现 ≥3 连板时 100% 产出溯源卡；对重组类标的 `exclude_flag` 必须为 1 |

### M3 资金聚合与风格研判（补钱潮能力）

| 项 | 内容 |
|---|---|
| 目标 | 让没有官方指数的"结构行情"也能算资金序列；给出大盘风格定性 |
| 输入 | `get_concept_blocks()`（个股→概念）+ `get_fund_flow()`（个股 20 日）→ 按 M1 的 basket 加总 |
| 处理 | ① 影子板块三日资金序列 ② 六态形态（加速流入/持续流入/流入放缓/流出放缓/持续流出/加速流出）③ 风格三维坐标（大小盘｜价值-成长｜业绩/主题驱动）+ **哑铃态判定**（防御端与成长端同时吸金、中间地带失血） |
| 输出 | `strategy_flow_shadow`（basket_id、D-2/D-1/D0、形态、可信度） |
| 已知限制 | 北向历史 2024-08 后上游停更 → 报告注明「北向历史缺失，仅用实时分钟级」，**不参与风格加权** |

### M4 宏观闸门（对应 G5）

| 项 | 内容 |
|---|---|
| 目标 | **只定权重与估值容忍度，不定板块方向** |
| 数据 | 新增 `ai_stock/dataflows/macro.py`：yfinance 取 US10Y(`^TNX`)、实际利率(`^TNX`−T10YIE)、美元指数(`DX-Y.NYB`)、USDCNH、油价(`CL=F`)、VIX(`^VIX`)、费半(`^SOX`)；DR007 尝试东财货币市场接口，取不到标缺失 |
| 处理 | 五变量 → R1~R6 regime 判定（附判定路径与置信度）→ 产出 4 件事：风格权重先验区间、**成长类评级上限**、最脆弱/最受益类别（不落个股）、**阈值型切换触发条件** |
| 硬约束 | 禁止"加息→科技跌"的直线推理，须过基准率表；缺失 ≥2 个变量则判 `未定`，且**不下调任何评级上限**（不猜方向） |
| 输出 | `strategy_macro_regime`；报告抬头必显 `regime + 成长评级上限` |
| 工作量 | 这是唯一需要新增数据源模块的一块（约 1 人日 + 联调） |

### M5 交叉验证裁剪器（对应 G3）

| 项 | 内容 |
|---|---|
| 目标 | 把三份独立产出对齐成一张矩阵，判「共振 / 背离 / 伪共振」 |
| 处理 | ① 以 **basket 为行**（不是板块名）对齐板块面/资金面/新闻面 ② 一致性判定：三方同向=✅共振；两方一致=⚠️；三方冲突=❌ ③ **同源检查**：三方关键事实若引自同一篇报道/同一家机构 → 标「伪共振」，置信度上限降为「中」④ regime 对账：一致升一档，背离 ≥3 日判「regime 可能切换」 |
| 输出 | `strategy_report.cross_matrix_json` |
| 实现方式 | **不用 LLM**，纯规则 + 数值对齐（同向判定用价格/资金/情绪的符号与分位）。省成本、可复现 |

### M6 记分闭环（对应 G4，**本方案的战略价值核心**）

| 项 | 内容 |
|---|---|
| 目标 | 每条可证伪断言留痕 → 到期自动回填 → 分组胜率 → **反哺权重** |
| 输出 | `strategy_prediction`（16 字段）、`strategy_scoreboard` |
| 自动回填 | 收盘后用当日行情/板块涨幅自动判定 `兑现/部分/证伪` 与 `move`（实测幅度），**禁止手工改 outcome** |
| 反哺机制（关键） | `driver` 分组胜率 → 生成 `driver_weight_coef`（0.8~1.2），写入 `quant_system_config`，被 `selection` 的行业优先级公式作为乘子；**样本 <30 条时只出观察，不出系数**（防过拟合） |
| 输出给用户 | 一句话诊断，如「并购重组驱动组 12 条胜率 25%，本期已下调该 driver 系数至 0.85」 |

## 6. 数据模型（7 张新表，全部 `QuantBase.create_all` 自动建，无需手工 DDL）

> 依项目既有约束：量化表无 Alembic 链路，给已有表加列必须手工 DDL；**因此一律新建表，不动现有表结构**。

```python
strategy_evidence      (id, trade_date, kind, source, payload_json, quality, fetched_at, ok)
strategy_structure_basket (id, trade_date, parent_board, basket_name, members_json,
                          synth_change_pct, valid_n, evidence_dist_json,
                          driver_consistency, rating_cap, verdict, created_at)
strategy_leader_trace  (id, trade_date, symbol, name, boards, board_type, official_board,
                        real_driver, attribution, fund_verdict, extrapolable, exclude_flag)
strategy_flow_shadow   (id, trade_date, basket_id, d2, d1, d0, pattern, confidence)
strategy_macro_regime  (id, trade_date, regime, vars_json, growth_cap, triggers_json, missing_json)
strategy_report        (id, trade_date, snapshot_type[close|intraday], sections_json,
                        cross_matrix_json, risks_json, prompt_version, created_at)
strategy_prediction    (id, period, type, target, driver, claim, direction, horizon,
                        confidence, falsify, magnitude, regime, crowding,
                        outcome, actual, move, base_rate, note)   -- 记分主表
strategy_scoreboard    (id, as_of, overall_win_rate, odds, by_type_json,
                        by_driver_json, calibration_json, diagnosis)
```

报告与断言分离：`strategy_report` 管展示，`strategy_prediction` 管记账，**同一份报告生成的断言必须能被单独回填**。

## 7. 技术架构与集成点

**队列**：新增 `STRATEGY_QUEUE`（与 `SELECTION_QUEUE` 并行、只读不交易），消费者数量 1，避免与交易队列争抢。
**Agent 基类**：全部继承 `ai_stock/quant/agents/base.py::BaseAgent`，自动获得 LLM 懒加载、`agent_decision_log` 审计、异常契约（业务结论不抛异常）。
**编排**：不新建 FSM，用一条固定顺序的 `strategy_flow`（`sector_structure → leader_trace → flow_shadow → macro_gate → arbiter → persist`），任一步失败则**降级为规则产出**并标记 `degraded=true`，不阻断后续步骤。
**调度**：`scheduler.py` 新增 `trigger_strategy_desk()`，15:05 入队（避开收盘瞬时接口压力）；可选 11:00 盘中快照，`snapshot_type=intraday` 且前端强制显示「结论未定局」，收盘后自动补一次 close 快照并**对照盘中断言生成修正项**。
**API**（`backend/app/api/strategy.py`）：`GET /api/strategy/desk?date=`、`/structure`、`/leaders`、`/scoreboard`；`POST /api/strategy/run`（支持 `--no-llm`/`--dry-run`）、`POST /api/strategy/verify`。
**前端**：`frontend/src/pages/StrategyDesk.vue`，复用现有 dark 主题与 ECharts，三 Tab。
**开关**（`quant_system_config`，热生效）：`strategy_desk_enable`、`strategy_intraday_enable`、`strategy_basket_min_valid_n=5`、`strategy_reproduce_coef_enable`（默认 0，观察两周后再开）。

## 7.5 时序契约与交易链路隔离（**回答"次日校验会不会影响当天交易"**）

### 结论

| 问题 | 答案 |
|---|---|
| 会不会影响**当天（T 日）**的交易？ | **不会，且物理上不可能**：15:00 已收盘（T+1 制度下当日买入本就不可卖），策略台在独立 `STRATEGY_QUEUE`、只读行情不写订单表，`pre_trade_check` 不读策略台任何结论。 |
| 会不会影响 **T+1** 的交易？ | **会，而且是设计意图**——但只能通过两条受控路径，且有"三不"红线。 |

### 受控路径（只有两条）

- **路径 A（选股池）**：T 15:20 报告落库 → **T 18:00 的 selection 槽位**读取（`effective_from = T+1 09:15` 的报告才可见）→ 改变自选池成分 → T+1 盘中 `buy_scan`（每 10 分钟）用新池子。
- **路径 B（权重系数）**：`driver_weight_coef` **周频**（每周一 07:00 前）重算，作为 `selection` 行业优先级的乘子。

### 三不红线（写进代码，违反即视为 bug）

1. **不动硬门槛**：仓位上限、`max_daily_orders`、`max_drawdown_pct`、交易时段闸门，一律不受策略台影响。
2. **不触发卖出**：报告把某板块降级为"观察"时，**禁止**产生卖单。持仓处置权归 `hold` 链路；策略台最多通过 `dyn_confidence` 衰减做软影响，且**不写 `quant_trade_log`**（会挤占当日下单额度）。
3. **不日频调权**：用 1 天结果改今天权重 = 把追涨杀跌自动化。必须 样本 ≥30 条 + 周频 + 限幅 0.8–1.2 + 开关默认关。

### 时序表（T = 报告所属交易日）

| 时刻 | 动作 | 与交易链路的关系 |
|---|---|---|
| T 15:00 | 收盘，当日交易终局 | — |
| T 15:05 | 策略台入队（独立队列，单消费者） | 不影响任何订单 |
| T 15:20 | 报告 + basket + 断言落库，`effective_from=T+1 09:15` | 只写 `strategy_*` 新表，单事务提交 |
| T 15:20 | **回填历史断言**：只回填 `verify_date ≤ T` 的断言，用 T 日**已收盘**日线 | 只改 `strategy_prediction` |
| T 15:35 | 既有 `daily_report` + `pool_expire` | 错峰在后，避免与策略台抢 config 写 |
| T 18:00 | selection 槽位 → 读策略台矩阵 | 影响自选池（路径 A） |
| T+1 07:00 | 盘前最后一槽 selection | 同上报 |
| T+1 09:30~15:00 | `buy_scan` 每 10 分钟 | 只读自选池与个股技术信号，**读不到策略台结论** |
| T+1 15:20 | 回填 T 日断言（此时才有完整日线） | 影响 T+2 的系数 |

### 三个必须处理的边界

1. **回填存在 1 个交易日的天然延迟**：T 日断言要等 T+1 收盘才有干净日线。**不得**用 T+1 盘中价回填——那等于把"未定局"当定局，是记分体系最常见的污染源。
2. **数据缺失不得判证伪**：T+1 若标的停牌或接口失败，记 `无法判定` 并 `excluded`，否则会把数据故障当成判断错误，导致权重被错误下调。
3. **盘中快照不记账**：11:00 快照产出的断言 `snapshot_type=intraday`，**不写入 `strategy_prediction`**（只进报告展示）。否则"盘中错、收盘改"会让胜率统计失去意义；收盘 close 快照才生成正式断言，并把盘中断言作为修正项对照呈现。

---

## 7.6 红线与隐患的落地校验（可自动化验证）

### 7.6.1 断言状态机（四态，不是三态）

```
pending ──(verify_date 到且日线完整)──> judged ──> 兑现 / 部分 / 证伪
   └────(停牌/接口失败/涨跌停无成交)────> unjudged（进分母？否）
```

- `strategy_prediction` 增列：`snapshot_type(close|intraday)`、`verify_state(pending|judged|unjudged)`、`unjudged_reason`。
- **`unjudged` 不计入胜率分母**（分母只算 `judged`）。理由：把数据故障当判断错误，会让一次接口封禁打掉整周权重。
- 判定前必须校验 `bar_date == verify_date` 且 `provisional == False`（指标已带这两个字段），不满足则回到 `pending`，**禁止退化为盘中价**。

### 7.6.2 三条自检（写进 P1 上线门禁，跑脚本判定）

| 自检 | 判据 | 失败含义 |
|---|---|---|
| S1 交易未被掐死 | 近 20 个交易日**每个交易日都有 trade_log 记录**（含 rejected） | 红线1 失效：分析结论变成了硬门槛 |
| S2 断言未被污染 | `count(snapshot_type=close) == count(prediction)` | 红线3 失效：盘中快照混入了统计 |
| S3 无法判定率可控 | 单 driver `unjudged / (judged+unjudged) ≤ 30%` | 数据质量不足，该 driver 本轮**不出系数**并在看板标注"未调整" |

### 7.6.3 盘中快照的价值回收

盘中断言不入账，但收盘执行一次 `reconcile`：逐条比对盘中断言与收盘实测，方向反转的写入 `strategy_report.correction_json`，前端报告顶部显示「本期修正 N 项」。**信息不丢，只是不进统计。**

## 10. 不做清单（明确取舍）

| 不做 | 理由 |
|---|---|
| 复刻"多空自由辩论" | 辩论不可复现、成本高、无法记账；单标的辩论已有 `agents/` 覆盖，市场级不需要 |
| 盘中实时滚动更新 | 与 T+1 交易节奏不符，且盘中结论不可信；只做定点快照 + 收盘定稿 |
| 让分析结论直接拦截下单 | 硬门槛已被证明会打穿交易量；只做权重乘子 |
| 自建新闻源抓取 | 新闻→主题体系已优于专家团，重复投入无收益 |
| 一次性追求"90% 复刻" | 先拿 P0 的两个规则型能力，先把错误率降下来 |

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 编造数字 | 证据引用制 + 裁决器校验；无 `evidence_id` 的断言自动标「观点」不入账 |
| 结构聚类把异源票混进篮子 | 驱动分类强制剔除并购重组类；有证据样本 <5 直接降级 |
| 反哺导致过拟合 | 样本 <30 不出系数；系数限幅 0.8–1.2；开关默认关 |
| 与交易链路争资源 | 独立队列 + 单消费者 + 4 次调用上限 |
| 数据源再次被封（东财 push2 已有先例） | 复用 `data_health` 熔断 + 多源降级；缺失即标「数据缺失」，不阻塞报告 |

## 12. 成功指标

**北极星**：`可交易信号条数 × 命中率` —— 不是为了多写报告，而是为了"给出的关注板块里，有多少真的能交易且方向的对了"。

过程指标：
1. 归因错误率（把独立事件写成板块启动的条数 / 总高标条数）目标 = 0；
2. 断言回填率 ≥95%（到期未回填即为流程失败）；
3. 分析结论消费率（`selection` 实际用到权重的行业占比）≥60%，衡量"报告是否活着"。

| 专家团能力 | 系统落点 | 是否需新数据 |

---

**一句话总结方案**：不复制专家团的报告，复制它的**纪律**——用「证据外键 + basket 有效性规则 + 断言记账 + 权重回灌」四根柱子，把一次性的高水平分析变成每天自动运行、且会因为错而被修正的系统能力。
